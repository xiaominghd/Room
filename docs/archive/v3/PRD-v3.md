# PRD v3.0

> 状态：V3.0 草案（2026-11-17），取代 11-16 的骨架版
> 依据：`VISION.md`、`AGREEMENTS.md`、11-16/17 的逐块讨论
> 范围：单实例、单房间、两个人。托管、多租户、订阅、iOS 都不在这一版。

---

## 1. 产品定义

**一个会忘的房间，一个不会忘的相册。**
话会收起来，照片可以留下。

- **房间**：只有两个人；消息在四周内收进图文卡；没有已读、在线、正在输入。
- **相册**：按天的记忆日历；留过的保原图，没留的留缩略图，没照片的只剩一个点。
- **门**：停是关门（真的收不到）；想聊是开门（写一张卡片）。

---

## 2. 用户与场景

| | 发起者 | 被邀请者 |
|---|---|---|
| 是谁 | 想用这个 App 的人 | 被拉进来的人 |
| 在意 | 能不能用、隐私说不说得清 | 麻不麻烦、会不会被监视 |
| 失败点 | 邀请发出去对方不来 | 要填服务器/地址/长码 → 放弃 |

四个真实时刻：睡前想说两句、吵到一半想停、想修复但开不了口、几个月后想看看那天。

---

## 3. 原则

**四条承诺**：不变、不记账、整理、留下。
- 整理：系统管聊天记录、生成图文卡、开门时问一句；不解释、不评价、不站队。

**一条底线**：不伪装——机器做的像机器，人做的像人，人没做的一个字都不说。

**一条方向**：给两个人一个地方，不给一套方法。
- 它是一个地方：有墙、有门、有抽屉、有管家
- 不装监控：没有已读、在线、输入中；但状态要说清（门关着、门口有卡片、留到几号）
- 表达是住进去之后自然发生的事，不是目标

**一条物理规则**：这扇门没有猫眼。开门是准备说话，不是来看一眼。

---

## 4. 结构总览

```
房间（聊天）
 ├─ 消息：文字 / 图片 / 语音
 ├─ 引用、撤回
 ├─ 日期行（一天收进卡后，房间里留下的那一行）
 └─ 输入区：文字 / 图片 / 语音

门（房间的状态）
 ├─ 停 = 关门：不接收、消息排队
 └─ 想聊 = 开门：AI 问一句、写一张卡片

相册（记忆）
 └─ 每天一张卡：AI 图文卡 + 此刻 + 小框
```

## 5. 账号与准入

### 5.1 身份

| 东西 | 作用 | 规则 |
|---|---|---|
| 手机号 | 唯一编号 | 全系统唯一；登录用；以后接实名 |
| 用户名 | 别名 | 房间内唯一；可改；**不能登录** |
| 密码 | 唯一凭证 | ≥ 8 位；允许纯数字 |

**没有恢复码、没有短信验证码、没有实名。** 密码是唯一凭证。

### 5.2 注册 / 登录 / 找回

- 注册：手机号（二次确认）+ 用户名 + 密码，注册完直接进房
- 登录：手机号 + 密码；refresh token 30 天；单设备，新登录踢旧
- 找回：**人工**
  1. 用注册手机号发短信到运营者号码，内容写「找回密码」
  2. 核对发送号码与注册号码一致
  3. 回一条 8 位临时密码（24 小时、一次、登录后强制改密）
  4. 非注册号发来，不处理
- 换手机号：密码 + 新号（二次确认）；旧号释放
- 退出登录：清本机；再登录回到同一间房

### 5.3 房间与邀请

- 第一个账号注册后自动建一间房，生成**房间 ID**（公开，如 `R7K2M9`），房主自己设 **6 位开房码**
- 邀请链接带房间 ID；第二个人注册后输入开房码
- 输入正确的开房码就直接进房，**不需要房主确认**；房间上限 2 人；满员后开房码立即失效
- 开房码就是门禁：谁拿到码谁就能进；分享前想清楚，进满后码立即失效
- 开房码可改、可撤销；只在这间房校验，不要求全局唯一

### 5.4 一个账号一间房

- 同一账号同时只能在一间房（留房期也算）
- 允许一个人注册多个号、进多间房（V3.0 接受，靠实名收口）
- **留房期 30 天**：离开或结束后，房间留 30 天；任一方说一句就回来，不设次数上限
- 留下的人随时可以「开始新的房间」，那间房立即关闭
- 安全退出：不产生留房期
- 注意：留房期是「房间」这层的门，说一句就回来，不写卡片；卡片只用于每天晚上的「停」

### 5.5 钩子（V3.0 不启用）

- `users.verification_level` / `users.identity_id`：将来接实名，一身份一房
- `/v1/verification/*` 返回 `not_enabled`
- 短信通道上线后：验证号码、自助找回、实名，一起接

## 6. 房间

### 6.1 能发什么

| 类型 | 规则 |
|---|---|
| 文字 | 最多 2000 字；多行；系统 emoji；纯文本，不解析链接 |
| 图片 | 一条一张；拍照或相册；长边压到 1600 |
| 语音 | 单条 60 秒；按住录、上滑取消 |
| 不做 | 表情包、文件、位置、名片、转发、多选、复制、搜索 |

### 6.2 发送

| 状态 | 用户看到 |
|---|---|
| 发送中 | 气泡立刻出现，右下小点，**不显示时间** |
| 已发送 | 小点消失，时间出现（服务端时间） |
| 失败 | 时间位置变 `没发出去 · 重发` |
| 重发中 | 回到发送中，同一条，不复制 |

- 按发送立刻清空输入框；失败不弹窗、不震动
- 自动重试 2 次（2s、8s）；之后手动重发
- `client_id` 幂等；退出 App 再回来，没发出去的那条还在
- 限流 30 条/分钟；超了提示 `一次说太多了`，草稿保留
- 草稿存本机，重启还在

### 6.3 接收

- 服务端分配 seq（每房间单调递增）；WebSocket 推送
- seq 接上就追加；有空洞先 `after_seq` 补拉；重复按 id 丢弃
- 排序只认 seq；断线重连先补拉
- 后台收推送；从通知进入滚到那条消息

### 6.4 时间

- 显示时间一律用**服务端时间**
- 离线消息显示服务端**接受时间**（20:00 没网、20:30 发出，显示 20:30）
- 日期分隔：今天 / 昨天 / `10 月 17 日`；跨年显示年份

### 6.4.1 消息在房间里的寿命

- 房间保留最近 **28 天**的原文
- 第 28 天，那一天收成一行 `10 月 17 日 · 已收进相册`，点开是相册的卡
- **留过的一天**：在留的当下就从聊天框收走，只留一行 `10 月 17 日 · 留过`，点开是卡
- 没留的一天：第 28 天原文删除，照片转缩略图

### 6.5 引用

- 长按 → `引用并回复`；引用**整段**，长文视觉折叠可展开，不截字
- 引用块不显示原消息时间；不套娃（只保留直接一层）
- **引用只记 id，不复制文字，按原消息当前状态实时渲染**
  - 0–7 天：全文
  - 第 7 天起：原消息进那天的卡，引用显示 `10 月 9 日 · 已收进日历`，点了跳过去
  - 原文撤回：`原消息已撤回`
- 引用不能比它指向的东西活得久

### 6.6 撤回

- 只有自己 2 分钟内的消息能撤；点了就撤，不二次确认
- 撤回后**完全消失**，对方侧淡出 120ms，不留痕
- 被引用过的那条撤回后，引用块显示 `原消息已撤回`

### 6.7 不做

已读、已送达、正在输入、复制、转发、多选、消息搜索、全局网络横幅。

## 7. 记忆

### 7.1 时间线（28 天）

| 时间 | 房间 | 日历 |
|---|---|---|
| 0–28 天 | 原文都在：文字 / 图片 / 语音 | 第 7 天起，有内容的那一天生成一张卡 |
| 每 7 天 | 不动 | 卡自己压一次（第 7 / 14 / 21 / 28 天） |
| 第 28 天 | 原文消失，只留一行 `10 月 17 日 · 已收进相册` | 卡定型，永久保留 |

- **有内容就有卡**：纯文字的日子也有卡，没有照片就不放照片
- 卡的文字长度与每周删减规则**待定**（以后专门做压缩算法）；先保证不压成一句
- 留过的一天：原文永久保留，卡冻结；没留的：第 28 天原文删除，照片转缩略图
- 特别记忆的原话单独保存，28 天后还在
- 压缩失败：这一天不生成卡，第 28 天只剩点

### 7.2 图文卡怎么写

- **先删后写**：先删结构性噪音（「嗯」「好」「收到」、重复、纯表情），再写成卡
- 照片按当天顺序排，最多 9 张；没有照片就不放
- 文字只写那天发生了什么：时间、地点、做了什么、和谁
- 卡上标「AI 整理」：这是机器写的，不冒充人话
- 删句红线：道歉、承诺、感谢、照片描述、带信息的话一律不删；不确定就保留
- **不保存争执**：不写指责、反问、翻旧账；一天只有吵架，就不生成卡，只留一个点
- 第三人称、用名字：`那天栗子下班买了糖炒栗子，给阿澄留了一点。`
- 不用「我」、不用「他/她」、不写情绪判断、不引原话
- **AI 不读引用块**：引用不能借压缩复活旧话
- 压缩算法（每 7 天删多少、留多少）**本版不定**，以后单独做

### 7.3 两种留

| | 在哪留 | 留什么 | 后果 |
|---|---|---|---|
| **留一天**（主） | 相册里点「留这一天」 | 原文 + 原图 + 图文卡 | 冻结整天；原文搬进卡里，从「看那天的原文」进 |
| **特别记忆** | 聊天长按一条 | 这句保原话；这张保缩略图并置顶 | 28 天后仍在 |

- 留一天只能留已经生成卡的日子（第 7 天起）；当天的日子不能留
- **留一天后，这一天从聊天框收走**，只留一行 `10 月 17 日 · 留过`；原文在卡里，不在聊天框
- 特别记忆：**谁标的谁删**；删了只在自己这边少一条，对方仍看到
- 28 天后：留一天的原文仍可看；没留的原话和原图都没了

### 7.4 此刻

一天一张卡，是两层：

- **AI 图文卡**：那天发生了什么；照片 + 文字；不可改
- **此刻**：那天你心里是什么；一句话；可选

规则：

- **一人一条**；只有本人能改、能删
- **唯一入口是相册**：打开那一天的卡，在卡下写；房间里没有入口、不提示、不推送
- **不参与压缩**：写在卡上就一直在，不随 AI 卡变短
- **AI 不读、不改、不接话**
- **28 天后仍然能写**：AI 卡定型，此刻是活的
- 不写就没有，不出现「还没有此刻」
- 可以不相关：`我爱你`、`今天很累`、`想抱抱你`，不需要解释那天发生了什么

### 7.5 照片与原文

- 留过的一天：原文永久保留；照片保留原图
- 没留、有照片：第 28 天原文删除；照片缩略图（长边 640），不能放大；卡还在
- 没照片：卡还在（纯文字）；月历格子里是一个点
- 门口等待的卡片不参与压缩；被取走后随当天压缩

## 8. 相册

### 8.1 形态

**活的记忆日历**：第 7 天起，有内容的一天进相册（带卡）；28 天内可以留；28 天后定型。

### 8.2 月历格子

| 状态 | 格子里 |
|---|---|
| 留过 | 清晰原图缩略 + 日期 |
| 没留、有照片 | 略柔的缩略图 + 日期 |
| 没留、没照片 | 小圆点 + 日期（点开是纯文字卡） |
| 什么都没有 | 空 |

- 只显示有内容的月份；一直往回翻；不做「那年今日」、不做搜索、不做统计

### 8.3 一天的卡

```
10 月 17 日

那天下了雨，他在便利店门口分了你一串关东煮。   ← AI 图文卡（2–4 句）

[缩略图] [缩略图] [缩略图]                     ← 照片网格，三列，最多 9 张

此刻
  栗子：我爱你
  阿澄：今天很累

┌──────────────────────┐
│ 「你先吃，我不饿」      │                     ← 特别记忆，小框，放最后
└──────────────────────┘

留过 / 留这一天
看那天的原文（留过才有）
```

### 8.4 隐藏与删除

- 隐藏一天：只影响自己，对方照常可见
- 删小框：标它的人可删，只在自己这边少一条
- 此刻：本人可改可删；对方不能动；隐藏一天时一起隐藏
- 不删天、不删照片、不做整体删除

### 8.5 空态

- 这个月没有：`这个月还没有`
- 整个相册没有：`还没有留下什么`

## 9. 门（停与想聊）

### 9.1 停 = 关门

- 输入框上沿一条光（把手）；按住上拉，房间随手指变暗
- 拉过阈值松手 → **门停在半关**（暗 50%），不直接关
- 半关时底部一行：`今晚到这儿`（可改，**不能空**）+ `关` / `算了`
- 5 秒不动 → 自动弹回；点「关」→ 门才真正关上
- 关门后：
  - 房间暗，只剩输入框一圈光
  - **收不到对方的消息**，消息排队
  - 不能发消息（要发就先开门）
  - 对方看到：`对方关着门` + 关门那句 + `你的消息会在对方开门时出现`

### 9.2 想聊 = 开门

**想聊只在停过之后存在。**

- 门关着时，顶部一条细光（把手）；按住下拉，房间随手指变亮
- 松手 → 门开：
  1. 排队的消息先出现（按原时间）
  2. 输入框上方浮出 AI 的一句问题，不挡消息
  3. 写一张卡片（1–2 句，最多 80 字）
  4. 递出去

### 9.3 卡片与锁

- 对方开着：卡片直接递到手里
- 对方关着：卡片**放在门口**；他开门时看到
- **开门需要一张卡片**：自己写的，或者门口对方留的那张
- 门口等待的卡片不压缩；取走后随当天压缩
- 一张卡片就是一次开门；每次开门一张

### 9.4 AI 在门里做什么

- 只在开门时问一句；问题前标「AI」；只读：关门那句、关门前最后几条消息、现在的时间
- 出的是邀请，不是审问：
  - `现在最想说什么？`
  - `昨天最让你担心的是哪一句？`
  - `想从哪一句开始说？`
- **不做复述**；不评价、不总结、不判断谁对谁错；失败就跳过

### 9.5 没有猫眼

- 关门期间看不到任何消息；想看，只能开门
- 开门是准备说话，不是来看一眼
- 停不是惩罚，是边界；关门那句就是它的作者

## 10. 通知

- **只推两件事**：新消息、一张卡片
- 不推：停 / 关门 / 想聊 / 门开了 / 卡片被取走 / 导出 / 结束
- **合并**：同一房间只保留一条消息通知；第一条响，后续更新同一条、不响，正文后加数字 `有新消息 3`
- 数字 = 自上次进房间以来的新消息数；进房间清零；`99+`
- 卡片单独一条，只写 `有一张卡片`
- 锁屏默认不显示内容；可在设置里打开，打开时写明代价
- **不做 App 图标角标**
- 关门期间，关门的人完全不推
- 点通知：消息还在 → 滚到那条；已压缩 → 那天的卡；已定型 → 相册那天的卡
- 权限：进房后、发第一条前，一句 `有人说话时，通知你。别的不会推。`
- 今晚不提醒：到第二天 8:00，不是“停”

## 11. 我的与设置

```
我的
├─ 资料卡：栗子 · 和 阿澄 在同一个房间        →
├─ 卡一（账号）：账号与安全 / 通知
├─ 卡二（房间）：导出 / 这个房间怎么运转
└─ 底栏：隐私政策 · 用户协议 · v1.0.0 · 反馈
```

- 一级不放开关；开关进二级
- 账号与安全：手机号（打码、换绑）/ 修改密码 / 退出登录 / 注销（最底、红字）
- 注销：7 天冷却，期间登录可撤销；执行后身份删除，共同相册只读留给对方
- 通知：新消息通知 / 锁屏显示内容 / 今晚不提醒
- 导出：范围（全部 / 近 30 天 / 近 7 天）、格式（PDF / 纯文本）、生成；对方收到一条提示；链接 7 天
- 运转说明：按新规则写（记忆、AI、停、想聊）；「怎么关掉」等结束定了再补
- 不做头像、多账号切换、免打扰时段、客服系统

## 12. 隐私与安全

| 项 | 规则 |
|---|---|
| 消息 | 28 天压缩；第 28 天原文删除，只剩卡 / 缩略图 / 点 |
| 相册 | 留过的原图永久；没留的缩略图；直到用户删除房间 |
| 账号 | 手机号 + 密码直到注销；不存证件、不存真名 |
| AI | 每 7 天读一次原文用于压缩；开门时读关门上下文；不留存、不训练；不读「此刻」 |
| 此刻 | 随当天卡保存；只本人可改删；AI 不读 |
| 找回 | 人工；只认注册手机号发来的短信 |
| 日志 | 不记消息内容、不记手机号、不记密码 |
| 备份 | 不含消息正文（删除不能被备份打脸） |
| 传输 | 全站 TLS；密码与令牌哈希；限流 |

## 13. 不做

- 说给自己、本机笔记（V3 删除）
- 已读、送达、在线、正在输入
- 复制、转发、多选、消息搜索
- 头像、个人主页、多账号切换
- 日记、纪念日、打卡、年度回顾、统计
- 推送钩子（“你很久没来了”）
- 表情商店、红包、文件、位置
- 公开注册、多租户、订阅、iOS（见 §16）

## 14. 指标

| 指标 | 目标 |
|---|---|
| 北极星：双人周留存 | 两个人都在 7 天内各打开 ≥ 3 天 |
| 邀请完成率 | ≥ 55% |
| 进房 → 第一条消息 | ≥ 70%，中位数 ≤ 60 秒 |
| 留的转化 | ≥ 20% 活跃房间每周至少留 1 天 |
| 通知关闭率 | < 30% |
| 28 天定型 / 相册丢失 | 0 |
| 导出成功率 | ≥ 99% |

## 15. 验收

- [ ] 注册 → 进房不需要问人；开房码输对就直接进房
- [ ] 关门后收不到消息；开门后消息按原时间出现；没有卡片开不了门
- [ ] 引用整段；原文进卡后引用显示「已收进日历」；撤回后引用显示「已撤回」
- [ ] 第 7 天有图文卡；第 28 天有卡片和缩略图，或一个点
- [ ] 留过的一天：原图可放大；特别记忆的原话不变短
- [ ] 通知合并成一条带数字；锁屏默认无内容；无图标角标
- [ ] 删除小框只在自己这边少一条
- [ ] 此刻：一人一条、只有本人能改删、28 天后还能写、房间无入口
- [ ] 忘密码：注册号发短信 → 临时密码 → 强制改密
