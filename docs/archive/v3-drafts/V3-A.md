# V3 · A 组：第一分钟（草案）

> 范围：从点开邀请链接，到发出第一条消息。
> 约定：只写 PRD，不动前端；结论进文档，不留在聊天里。
> 目标：**第二个人从点链接到提交开房码 ≤ 90 秒，中间不需要问人。**

---

## 0. 流程图（五步）

```
点开邀请链接（房间 ID 已带入，不手输）
   │  没装 App ──▶ H5 落地页 ──▶ 应用商店 ──▶ 首次打开
   │  装了 App ──▶ 直接进 App
   ▼
注册 / 登录：手机号 + 密码
   ▼
输入开房码（房主自定的 6 位）
   ▼
等房主确认
   ▼
进房：空态 + 「这儿还只有你」+ 输入框可写
   ▼
发出第一条消息
```

**五步。** 手机号注册（不验证）、不传证件、不设恢复码；房间 ID 由链接带入，只输 6 位开房码。

这五步里：不能要求先填资料、不能出现第二个 App、不能出现第二个密码；房主确认是唯一需要等的一步。

> **A0 准入**：邀请制、一人一房、留房期 30 天——三条硬规则见 [V3-ADMISSION.md](V3-ADMISSION.md)。
> V3.0 用手机号注册、不发验证码、不做实名；实名与短信验证留钩子，上架前再接。

---

## A1. 邀请落地页（H5）

**触发**：对方点开 `https://<server>/i/<code>`，手机上没有 App。

**页面结构（一屏，不用滚动）**

| 位置 | 内容 |
|---|---|
| 上 | 房间 logo（和启动页同一个） |
| 主标题 | 有人给你留了一个房间 |
| 副标题 | 这个房间只住两个人。话七天后消失，照片可以留下。 |
| 说明 | 房间 ID 已随链接带入，装好后不用再输。 |
| 主按钮 | 下载「房间」（Android） |
| 次按钮 | 已经装了？直接打开 |
| 脚注 | 一间房只有两个位置。 |

**规则**

- 落地页只做三件事：说明这是什么、给下载、把码带过去；**不注册、不填表、不登录**。
- 邀请码只出现在链接里，页面上不展示明文，避免被截图转发。
- 链接失效时，按钮置灰，正文换成对应状态文案（见 A5）。
- 落地页不收集任何设备信息。

**文案（定稿）**

- 主标题：`有人给你留了一个房间`
- 副标题：`这个房间只住两个人。话七天后消失，照片可以留下。`
- 带上房间：`房间 ID 已经带上了，装好直接进来。`
- 主按钮：`下载「房间」`
- 次按钮：`已经装了，打开`
- 脚注：`一间房只有两个位置。`

## A1.5 房间 ID 与开房码（对齐准入）

| 码 | 谁发 | 什么时候用 |
|---|---|---|
| 房间 ID | 建房时生成，公开 | 放在链接里，负责「找到哪间房」 |
| 开房码 | 房主自己定 6 位 | 手输，负责「证明你被邀请」；满 2 人立即失效 |
| 手机号 | 唯一编号 | 登录；忘密码走人工找回；一个手机号一个账号 |

落地页带的是**房间 ID**；开房码由房主另外告诉对方，不出现在链接里。

## A2. 房间 ID 带入

- 链接 → App：Deep Link / Universal Link 直接把房间 ID 交给 App，**用户永远不需要手输房间 ID**。
- 如果系统拦截了跳转（比如从微信打开）：落地页给一次「复制链接 → 用浏览器打开」的提示，仍然不手输房间 ID。
- App 内如果拿不到房间 ID（极端情况）：只显示「房间 ID 没带过来」，附一个「重新打开链接」按钮；**不提供手输框**，避免输错后以为是码坏了。

**验收**：从点链接到注册页，一次输入都没有。

## A3. 注册

### 字段

| 字段 | 规则 | 说明 |
|---|---|---|
| 手机号 | 11 位，唯一 | 唯一编号；登录用它；忘密码走人工找回（见 V3-ACCOUNT）；注册页二次确认 |
| 用户名 | 1–12 字，房间内唯一 | 别名，只用来显示；随时可改；**不能用来登录** |
| 密码 | ≥ 8 位 | 允许纯数字；不强制大小写（会逼人写在便签上） |

**注册页只要**：手机号（编号）、用户名（别名）、密码。不要邮箱、头像、生日、性别。

**V3.0 不收集证件**。手机号是登录凭证，必须存（加密 + 唯一索引）；将来接实名时，单独一屏，只存「通过/不通过」和身份哈希。

### 恢复码（没有这个东西）

V3.0 整个去掉恢复码：注册完直接进房。
忘记密码 = 用注册手机号发短信给运营者 → 人工核对 → 回临时密码（见 [V3-ACCOUNT.md](V3-ACCOUNT.md) §3.3）。
设计稿里的「恢复码」页不上线。

## A4. 进房第一屏

**新房间（对方还没进来）**

```
（房间头：我们的房间）
（空态区）
    [房间 logo]
    不用做什么
    这儿还只有你
（输入栏，可直接写）
```

- 不放教程、不放箭头、不放「第一步」。
- 空态区的两句话是**两层意思**：「不用做什么」是房间的态度，「这儿还只有你」说明安静的原因（对方还没来）。
- 输入框直接可用，第一条消息发出去就是普通消息，不做「欢迎消息」。

**对方已经进来、但还没说话**

- 只保留 `不用做什么`；`这儿还只有你` 永久消失。

**已经有消息**

- 不显示空态；进来停在最新一条。

**验收**：第一次打开的人 10 秒内知道「这里可以直接说话」。

## A5. 错误与边界文案

| 状态 | 文案 | 按钮 |
|---|---|---|
| 邀请过期 | `这个邀请过期了。让对方再发一个。` | 置灰 |
| 邀请已用 | `这个邀请已经用过了。让对方再发一个。` | 置灰 |
| 房间满员 | `这个房间已经满了。` | 置灰 |
| 码没带过来 | `邀请码没带过来，重新打开链接试试。` | `重新打开` |
| 网络失败 | `没连上。检查一下网络。` | `重试` |
| 昵称重复 | `这个名字房间里已经有人用了。` | 留在原页 |

**统一语气**：只陈述事实 + 给一条出路；不出现「你怎么才来」「你来晚了」「邀请无效」这类带评价的词。

---

## A6. 「这儿还只有你」的出现规则

- 判定依据：**对方的 membership 是否存在**，不看消息数、不看是否说过话
- 出现时机：每一次打开房间，直到对方注册完成
- 消失后：永久不再出现，哪怕对方之后一个月没说话
- 不做「对方最后在线」「对方还没看」这类补充信息

## 6. 指标（A 组）

| 指标 | 目标 |
|---|---|
| 邀请链接 → 进房完成 | ≥ 55% |
| 进房完成 → 第一条消息 | ≥ 70%，且中位数 ≤ 60 秒 |
| 点链接 → 提交开房码 | 中位数 ≤ 90 秒 |
| 提交 → 房主确认 | 中位数 ≤ 10 分钟（房主在线的正常情况） |
| 落地页 → 下载点击 | ≥ 40% |
| 邀请失败（过期/已用/满员）占比 | < 10% |

---

## 7. 不做

- 手机号/微信登录
- 手输邀请码
- 注册引导多步（头像、兴趣、关系类型）
- 「对方还没来」的推送提醒
- 落地页上的用户评价、截图轮播、功能介绍长图
