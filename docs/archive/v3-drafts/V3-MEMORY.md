# V3 · 记忆：分级压缩

> 更新于 2026-11-16。属于 PRD，不动前端。
> 核心：**话不一次性删掉，而是按比例变短；四周后，有画面的日子留下画面和一句话，没画面的只剩一个点。**

---

## 0. 初衷

- 这个产品先是为「吵架时别激动」准备的：话会散，不记账。
- 但温情的一面是记录：当时不值钱，几个月后才值钱；写日记太累，没人会翻聊天记录。
- 所以：**记录必须发生在当天，回看必须发生在很久以后；中间要有一个坡度，不是一道悬崖。**

---

## 1. 压缩算法

### 1.1 一句话

**按当天对话的总量，用一个固定比例压；压到 12 字为止；四周后只保留「画面 + 12 字」。**

### 1.2 分级：先删，再写成短记

不是把每句话砍短，而是：**先删掉无关的句子，再把剩下的写成一段短记。**

| 年龄 | 做什么 | 留下的形态 |
|---|---|---|
| 0–7 天 | 不读 | 原文 |
| 第 7 天 | 读一遍这一周：删结构性噪音 → 写成短记 | 2–3 句，30–120 字（按当天内容量比例，默认 15%，有上下限） |
| 第 14 天 | 只读上一版短记：删掉最不重要的一句 | 1–2 句，20–60 字 |
| 第 21 天 | 只读上一版：压成 1 句 | 12–40 字 |
| 第 28 天 | 定型 | 有照片：缩略图 + 12 字；没照片：点 + 日期 + 条数 |

**为什么要“先删”**：一天的对话里，一半是「嗯」「好的」「哈哈哈」「你到了吗」。这些不应该占掉留下的字数。删掉它们，剩下的话才有地方放。

**为什么不是逐句砍**：逐句砍会把一句完整的话砍成半句，读起来像坏掉的电报；先删后写，留下的是一段能读的话。

### 1.2.1 删什么、留什么

| 删（结构性噪音） | 留（一律保留） |
|---|---|
| 纯应答：「嗯」「好」「收到」「在」 | 带信息：时间、地点、事情 |
| 重复的话（同一意思说了两遍） | 带承诺：「明天我去接你」 |
| 纯表情、纯语气词 | 带道歉、带示弱、带感谢 |
| 打断、@、无内容的追问 | 带问题与回答 |
| 系统性的「哈哈」刷屏 | 描述照片的那一句 |

**不确定就保留。** 删错一句道歉，比留下十句废话严重得多。

**不保存争执。** 争吵里的指责、反问、翻旧账，不进短记；只写事实（几点、在哪、做了什么）。如果那一天只有吵架，短记留空，只留一个点——记忆不该替人保存「他当时怎么说的」。

### 1.2.2 写成什么样：短记，不是日记

- **第三人称，用名字**：「那天栗子下班买了糖炒栗子，给阿澄留了一点。」
- **不用「我」**：房间是两个人的，卡片也是两个人看的，第一人称没有主人
- **不用「他/她」**：不预设性别，用名字或「对方」
- **不写情绪判断、不写评价、不写谁对谁错**
- **不引原话**，但可以保留原话里的名词（糖炒栗子、窗台、便利店）

它读起来像日记，但不是「谁的日记」——它是这间房的短记。

### 1.3 画面

- **留过的天**：那天的照片保留**原图**
- **没留、但有照片的天**：照片压成**缩略图**（长边 640），和 12 字一起留在日历上
- **没照片的天**：不留画面，只剩一个点 + 日期 + 条数

所以「相册」从「你留的照片」变成「记忆日历」：**缩略图是记忆，原图是留。**

## 2. 两种留

### 2.1 留一天（主）

在相册里点「留这一天」：

- **冻结**：这一天不再压缩
- **取最长**：从已存版本里取最长的一版
- **原图**：这一天的照片全部保留原图
- **搬家**：进相册，成为一张卡：日期 + 短记 + 原图
- **不再压缩**：房间里这一天变成实心点

### 2.2 特别记忆（单句、单张）

在聊天里长按一条 →「特别记忆」：

- 只保护这一条，**不冻结整天**，那天照样压缩
- 这句话**保原话**：AI 删句时跳过它，缩短时不改它
- 这张照片**保缩略图**并置顶；原图仍然要留一天
- **谁标的谁删**：删掉的是这个标记，不是删对方说过的话
- 整天的短记里不会因为它而多写什么

### 2.3 两种的关系

留一天是承诺；特别记忆是给一句话加一点重量。
两个都能在 28 天内做；28 天后原话和原图都没了，两个入口都关。

## 3. 四级在界面上长什么样

| 年龄 | 房间 | 相册 |
|---|---|---|
| 0–7 天 | 正常气泡 | 没有 |
| 7–28 天 | 气泡被替换成一行灰字：「那天下了雨，他在便利店门口分了你一串关东煮」 | 没有 |
| 28 天后 | 实心点（留过）或空心点（没留） | 留过：原图 + 最长那句；没留但有照片：缩略图 + 12 字；没照片：点 + 日期 + 条数 |

- 点开空心点：只有「10 月 9 日 · 3 条」，没有内容
- 点开有缩略图的点：12 字 + 一张模糊的缩略图，不能放大
- 点开实心点：那天的卡，原图 + 那句
- 不做搜索、不做列表、不做「那年今日」

## 4. 压缩怎么写

| 规则 | 说明 |
|---|---|
| 只读一次原文 | 第 7 天读这一周的原文；之后只读上一版短记，不再碰原话 |
| **不读引用块** | 引用只属于原消息所在的那一天，不能借引用把旧话带进新一天 |
| 先删后写 | 先按 §1.2.1 删噪音，再写成短记；不是逐句缩字 |
| 只删不编 | 短记里的每个事实都要能在剩下的句子里找到；不能补因果、补情绪 |
| 禁词 | 「感受」「建议」「一起」「其实」「很明显」出现即重写 |
| 长度 | 按当天内容量算，有地板有天花板（见 §1.2） |
| 失败 | 返回空；这一天不生成短记，第 28 天只剩点 |
| 不确定就保留 | 删句时宁可多留，不可删掉道歉与承诺 |
| 特别记忆不删 | 被标记的句子不删、不缩短；被标记的照片置顶 |

## 5. 隐私

- AI 每周读一次**上一周的原文**（第 7 天），这是为了压缩，不是为了分析
- 之后不再读原文；第 28 天原文删除
- 注册时要写清楚：「为了让旧话变短，AI 每 7 天会读一次上一周的话，只用来压缩，不留存、不训练」
- 可以关：关掉之后第 7 天不生成句子，直接进入「点 + 条数」
- 关掉不影响「留」：留仍然可用，只是留给你的是一张只有日期的卡

## 6.6 文案规则

这是 App，不是落地页：

- **不写长段解释**。产品规则放到「这个房间怎么运转」那一页，主界面一个字都不解释
- 主界面最多一行短句（比如空态那句「不用做什么」），不写「一周后变一句、四周后剩一个点」这种说明书
- 门面那句「话七天后消失」删掉，不用另一段话补上
- 用户第一次遇到「话变短」时，不弹窗、不解释原因
- **不解释机制**：压缩比例、几天一级、缩略图与原图的区别，全都不出现在界面上，也不写进设置
- 机制只出现在**产品介绍的一页**里，而且只讲一件事：AI 帮你纪念。不讲怎么做

## 7. 反模式

- 压缩后还能搜索原文
- 每天提醒「今天的话要变短了」
- 把 12 字那句攒成时间线、年度回顾
- 用「你很久没留了」拉人回来
- 缩略图也做成可放大、可导出（那就等于没删）
