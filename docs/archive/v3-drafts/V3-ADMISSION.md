# V3 · 准入：手机号、一房、留房期

> 更新于 2026-11-16。属于 PRD，不动前端。
> 本版简化：**手机号注册、不发验证码、不做实名**；一个号一间房；留房期 30 天。
> 本条修订 `PRD-v2.md` §3.5「房间不可复活」——v2 落地时以本文为准。

---

## 0. 为什么

这个产品为**长期关系**准备，不想让「短择」的人进来。V3.0 的准入只保留三件事：

1. **手机号注册**：一个号一个账号；
2. **一个账号一间房**：房间两人上限；
3. **留房期 30 天**：离开后房间留 30 天，说一句就回来。

实名与短信验证**现在不做**，留钩子（§6）。所以 V3.0 只能做到「一个号一间房」，做不到「一个人一间房」——一个人注册几个号，就能进几间房。前期接受，以后靠实名收口。

---

## 1. 四条规则

| # | 规则 | 说明 |
|---|---|---|
| R1 | **手机号注册** | 手机号唯一，一个号一个账号；不发验证码，填了就算 |
| R2 | **一个账号一间房** | 同一账号同时只能在一间房（留房期也算） |
| R3 | **两人上限** | 一间房最多两个人；满员后房间码立即失效，不再进人 |
| R4 | **留房期 30 天** | 每次离开或结束，房间保留 30 天；说一句就回来，不设次数上限 |

## 2. 手机号、用户名与登录

### 2.1 三个东西，别混

| 东西 | 作用 | 规则 |
|---|---|---|
| **手机号** | 唯一编号：登录、找回、以后接实名 | 一个手机号一个账号；全系统唯一 |
| **用户名** | 别名：只用来显示 | 房间内唯一；随时可改；**不能用来登录** |
| **密码** | 登录凭证 | ≥ 8 位；允许纯数字 |

一句话：**手机号是身份证，用户名是名片。**
名片可以换，身份证不能重号。
- 换机、找回、以后接实名，都从这串号出发
- 一个手机号一个账号，天然挡住「随手注册一堆」

### 2.2 不验证的代价（接受）

| 代价 | 说明 | 以后怎么补 |
|---|---|---|
| 占号 | 别人可以填你的号注册，你反而注册不了 | 接短信验证 |
| 一人多号 | 一个人办几个号，就能进几间房，绕过留房期 | 接实名，按身份收口 |
| 号码写错 | 没有验证码，写错了也没人发现 | 注册页二次确认号码 |

V3.0 接受这三条：早期只有几十个人，出了问题你能人工处理。

### 2.3 登录与换号

- 登录：**手机号 + 密码**（用户名不能登录）
- 找回：**V3.0 人工**；短信上线后改成「手机号 + 验证码 + 新密码」
- 换号：密码 + 新手机号（没有短信，无法验证新号归属，早期接受）
- 换号后旧号释放，可以再注册新账号——这会让「一个人多号」更容易，属于同一类风险
- 改用户名：随时，只影响显示，不影响登录与找回

### 2.4 存什么

| 存 | 不存 |
|---|---|
| 规范化手机号（唯一索引，用于登录） | 通讯录、通话记录 |
| 密码哈希（Argon2id） | 密码明文 |
| 账号创建时间、核验状态（默认 none） | 身份证、真实姓名（V3.0 不收集） |

手机号是登录凭证，必须存；隐私页要写清「我们存你的手机号，用于登录」。

## 3. 开房码与进房

### 3.1 开房码

- **6 位数字，房主自己定**
- 只在**这一间房**里校验，**不要求全局唯一**（两间房都可以用 888888，互不影响）
- 唯一入口是「**房间 ID + 开房码**」：链接给房间，码给钥匙
- 房间满 2 人后立即失效
- 房主可以随时改；改完旧码立刻失效
- 不设过期时间（房间一直不满，码就一直有效）

### 3.2 进房流程

1. 点开链接：链接里带**房间 ID**（公开编号，不是秘密）
2. 注册 / 登录：个人 ID + 密码（个人 ID 就是手机号）
3. 输入**开房码**（房主自己定的 6 位，秘密）

```
房间 ID   R7K2M9            ← 链接带过来的，不用输
开房码    732914            ← 只有知道的人能进
```

4. 房主确认：

```
有人想进你的房间 · 阿澄
        [ 让 TA 进来 ]  [ 不是这个人 ]
```

5. 同意 → 进房，开房码立即失效；拒绝 → 申请作废，码不失效；不点 → 24 小时自动作废

为什么要「房间 ID + 码」两个：房间 ID 在链接里，负责「找到哪间房」；开房码负责「证明你被邀请」。两个分开，码泄露也不能乱进——还要房主点确认。

### 3.3 实名用户免码（V4，现在不做）

- 通过实名的用户，身份已经绑定唯一房间
- 登录并核验手机号后，直接进自己的房间，不需要开房码
- 前提是「一个身份一间房」已经生效（§6.1）

### 3.4 防猜

6 位 = 100 万种，自定码很容易被猜（123456、生日、手机尾号）。

| 措施 | 规则 |
|---|---|
| 限流 | 每个账号每小时最多试 5 次，超了锁 1 小时 |
| 锁定 | 同一 IP 连续失败 20 次，锁 1 小时 |
| 双因素 | 必须同时知道对方手机号与开房码 |
| 确认兜底 | 猜中也进不去，要房主点「让 TA 进来」 |
| 提示 | 失败只说「不对」，不区分「没这间房」和「码错了」 |

## 4. 留房期

### 4.1 一句话

**每次离开或结束，这间房都留 30 天。说一句话就回来，不设次数上限。**

### 4.2 状态机

```
在房里 ──离开 / 结束──▶ 留房期 30 天
   ▲                        │
   │                        ├─ 任一方说一句 ──▶ 回到房里
   │                        │        │
   │                        │        └─ 再离开 ──▶ 重新留 30 天（循环）
   │                        ├─ 留下的人「开始新的房间」──▶ 关闭
   │                        └─ 30 天到期 ──▶ 关闭
   ▼
关闭后：相册只读保留；双方可以开新房
```

### 4.3 留房期里谁能做什么

| | 离开的人 | 留下的人 |
|---|---|---|
| 看相册 | 能 | 能 |
| 看最后的消息 | 能（本来就 7 天内） | 能 |
| 说话 | **能，说一句就回来** | 能，同样说一句就回来 |
| 开新房 | 不能（这间房还留着你） | 能（开始新房 = 这间房关闭） |
| 再离开 | 回来后再走，重新留 30 天 | 同左 |

### 4.4 退房（离开）是什么

- 不需要对方同意，和「停」一样
- 不推送对方，对方下次打开才看到一句事实
- 一次确认页：房留 30 天、可以回来、相册可以先带走
- 不是删房间、不是删相册、不是拉黑
- 被留下的人**当天就可以开新房**

### 4.5 文案（定稿）

**离开前**

```
离开后，这间房会留 30 天。
你可以回来，也可以等它到期。
相册你可以先带走。
                          [ 再想想 ]  [ 离开 ]
```

**离开的人再打开**

```
这间房留到 3 月 18 日。
说一句话，它就回来。
（相册仍可看）
```

**留下的人看到**

```
对方离开了 · 这间房留到 3 月 18 日
说一句话，它就回来。        开始新的房间
```

**到期后**

```
结束 · 3 月 18 日
相册还在。
```

不出现：倒计时、「还剩 27 天」、「对方已放弃」、「最后一次机会」。

## 5. 数据

```sql
users(
  id uuid pk,
  phone_e164 text unique not null,      -- 登录凭证，必存
  password_hash text not null,
  recovery_hash text not null,
  display_name text,
  verification_level text not null default 'none',  -- none | phone | identity
  identity_id uuid,                     -- 现在为空，将来接实名
  created_at timestamptz
)

-- 一个账号一间房
create unique index one_active_room_per_account
  on memberships(user_id) where left_at is null;

-- 房间 ID：公开编号，出现在邀请链接里
alter table rooms add column public_id text unique not null;  -- 如 R7K2M9

-- 开房码：房主自定 6 位；唯一入口是「房间 ID + 码」，码本身不全局唯一
room_codes(code text not null, room_id uuid, created_by uuid,
           created_at timestamptz, revoked_at timestamptz)
create unique index one_active_code_per_room
  on room_codes(room_id, code) where revoked_at is null;

-- 留房期（subject_key 现在写 'u:<user_id>'，将来写 'i:<identity_id>'）
room_holds(room_id uuid pk, until timestamptz, left_by uuid,
           subject_key text not null, created_at timestamptz,
           closed_at timestamptz, close_reason text)
```

## 6. 钩子：实名与身份级一房

### 6.1 实名（现在不做）

- 字段：`users.verification_level`、`users.identity_id`
- 接口：`/v1/verification/identity` 现在返回 `not_enabled`
- 接上之后：`identity_id` 写入，一房判定从「按账号」换成「按身份」：

```sql
create unique index one_active_room_per_identity
  on memberships(identity_id) where left_at is null;
```

- 同一个身份换号重注册，也会被这条索引挡住

### 6.2 短信验证与找回（现在不做）

- 接口：`/v1/verification/phone`、`/v1/auth/recover` 现在都返回 `not_enabled`
- 上线后同时解决三件事：验证号码、找回密码、为实名铺路
- 找回流程：手机号 + 验证码 + 新密码
- 上线后找回可以自助，不再需要人工

### 6.3 什么时候必须开

1. 上中国区应用商店（社交类要真实身份认证）
2. 开放注册、不再人工控制分发
3. 出现批量注册 / 一人多号
4. 开始收费

打开时只对新账号要求；存量账号不追溯。

## 7. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 占号 | 真实机主注册不了 | 人工处理；以后接短信 |
| 一人多号 | 绕过「一房」和留房期 | 接受；实名后按身份收口 |
| 号码写错 | 找不回账号 | 注册页二次确认；忘密码只能人工核实 |
| 房间码外流 | 陌生人申请进来 | 房主确认；拒绝即作废 |
| 上架要实名 | 到那时必须开钩子 | 字段与接口已留 |
