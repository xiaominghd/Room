# V3 · 账号与用户管理

> 属于 PRD，不动前端。
> 结论：**账号功能要做；头像不做；恢复码这个概念不要；忘记密码走「注册手机号发短信给运营者 + 人工重置」。**
> 账号模型见 [V3-ADMISSION.md](V3-ADMISSION.md) §2；第一分钟见 [V3-A.md](V3-A.md)。

---

## 0. 结论

| 要做（V3.0） | 不做（V3.0） |
|---|---|
| 注册、登录、退出登录 | 头像、个人主页 |
| 改用户名（别名） | 绑定微信 / QQ / 一键登录 |
| 改密码 | 多设备同时在线 |
| 换手机号 | 账号切换 / 多账号管理 |
| 注销账号（7 天冷却） | 好友、通讯录、邀请记录 |
| 忘记密码：**短信 + 人工重置** | 恢复码、安全问题、自助找回 |
| 隐私政策、用户协议、版本号、反馈入口 | 会员等级、成长值 |

判断标准还是那三问：会不会让房间变脸？会不会把话变成证据？会不会多一个要维护的东西？
**头像三个都占**：要上传、要审核、要存储、要默认图、要裁切，而设计稿里根本没有头像位——加它等于改设计，这一轮约定不动设计。

## 1. 账号模型

| 东西 | 作用 | 规则 |
|---|---|---|
| 手机号 | 唯一编号 | 全系统唯一；登录；找回时用来核对 |
| 用户名 | 别名 | 房间内唯一；可改；不能登录 |
| 密码 | 唯一的凭证 | ≥ 8 位；允许纯数字 |

**没有恢复码。** 忘记密码不能自助，只能人工重置（§3.3）。

```
启动
 ├─ 已登录 ──▶ 房间
 └─ 未登录 ──▶ 登录页 ──▶ 注册页 / 忘记密码说明页

我的
 ├─ 个人资料（用户名、房间、加入时间）──▶ 改用户名

 ├─ 通知
 ├─ 导出
 ├─ 这个房间怎么运转
 └─ 隐私政策 / 用户协议 / 版本号 / 反馈
```

新增页面只有三个：**登录页、忘记密码说明页、账号与安全页**。
设计稿里的「恢复码」页**不上线**，这个概念整个去掉。

## 3. 流程与文案

### 3.1 登录

- 字段：手机号 + 密码
- 保持登录：refresh token 30 天；打开 App 不用每次输
- 单设备：新登录踢掉旧设备（旧设备清空）
- 错误统一：`手机号或密码不对`（不提示哪个错、不提示账号是否存在）
- 底部两个入口：`没有账号，注册` / `忘记密码`

### 3.2 注册

- 字段：手机号（二次确认）+ 用户名 + 密码
- 手机号重复：`这个手机号已经注册过了。用原来的账号登录。`
- 用户名重复：`这个名字房间里已经有人用了。`
- 注册完直接进房，不设恢复码、不做欢迎引导

### 3.3 忘记密码：短信 + 人工重置

**用户这一侧**

1. 点登录页的「忘记密码」，看到一页说明
2. 用**注册时那个手机号**，发一条短信到运营者的号码
3. 短信内容写：`找回密码`（不写新密码、不写身份证）
4. 等回信：核对通过后，回一条**临时密码**
5. 用临时密码登录 → 强制改密码 → 进房

页面上的原话：

```
忘记密码
用你注册时的手机号，发短信到 138 xxxx xxxx
内容写：找回密码
我们核对是你本人之后，回你一条临时密码。
不是这个号码发来的，我们不处理。
```

**运营者这一侧（不是产品功能，是操作流程）**

1. 收到短信，看发送号码
2. 在后台查这个号码对应的账号
3. 号码一致 → 生成一次性临时密码（8 位），回短信
4. 号码不一致 / 没有这个号 → 不回
5. 后台记一笔：时间、号码、操作人（不记短信内容）

**规则**

| 项 | 规则 |
|---|---|
| 临时密码 | 8 位，24 小时有效，用一次作废 |
| 登录后 | 强制改密码，不改不能进房 |
| 会话 | 重置时踢掉所有设备 |
| 频率 | 同一号码 1 次 / 天 |
| 处理时效 | 写明「不是实时，通常 24 小时内」 |
| 成本 | 用户自己发短信，我们不需要短信通道 |

**为什么这样做**：不接短信网关、不买短信套餐、不做自助找回，但又能确认「发短信的人就是注册的人」。早期几十个人，这个量人工扛得住。

**它的边界**（要写进帮助页）：

- 注册号码换了、或者 SIM 卡丢了 → 找不回，只能人工判断（通常没辙）
- 短信发送号码可以被伪造（极少见），接受这个风险
- 运营者要有一个专门的工作号码，不要用私人号

### 3.4 改用户名

- 入口：我的 → 个人资料 → 更换
- 1–12 字，房间内唯一；改完立刻生效
- 只影响显示，不影响登录、房间关系

### 3.5 改密码

- 需要：旧密码 + 新密码
- 成功后**踢掉其他设备**（本机保持登录）
- 密码错误次数限流：5 次 / 小时

### 3.6 换手机号

- 需要：密码 + 新手机号（二次确认）
- 没有短信，无法验证新号归属；这是已知风险，早期接受
- 成功后旧号释放；旧号可以再注册新账号
- 换号不影响：房间、相册、留房期

### 3.7 退出登录

- 清掉本机 token
- 再登录回到同一间房

### 3.8 注销账号

- 需要：密码 + 输入「注销」两个字
- 冷却 7 天：7 天内登录可撤销；7 天后执行
- 执行后：身份与登录删除；**共同相册转为只读留给对方**
- 若房间还在留房期，注销视为「离开」，对方仍可回来

## 4. 会话与安全

| 项 | 规则 |
|---|---|
| access token | 15 分钟 |
| refresh token | 30 天，单设备，服务端存哈希 |
| 敏感操作 | 改密码 / 换号 / 注销要密码 |
| 限流 | 登录 5 次/小时；换号 1 次/天 |
| 日志 | 只记 user_id 哈希、路由、结果；不记手机号与密码 |
| 异地登录 | 不做提示（没有这个产品语言）；新登录直接踢旧 |

**忘记密码 = 进不去，只能人工。** 相册还在对方那里，不会丢。这段话写在登录页和帮助页里。

---

## 5. 与房间的关系

- 账号是账号，房间是房间：退出登录不等于离开房间
- 注销才算离开；注销后相册只读留给对方
- 换手机号不改变身份，房间不变
- 以后接实名：`identity_id` 绑到账号上，一个身份一间房

## 6. 上架必需的杂项

| 项 | 放在哪 | 优先级 |
|---|---|---|
| 隐私政策 | 我的底栏 | P0（商店硬要求） |
| 用户协议 | 我的底栏 | P0 |
| 注销账号入口 | 账号与安全 | P0（商店硬要求） |
| 版本号 | 我的底栏 | P1 |
| 意见反馈 / 客服号码 | 我的底栏 + 忘记密码页 | P1 |
| 权限说明（相册、麦克风） | 首次触发时 | P0 |
| 未成年人提示 | 隐私政策内 | P1 |

不做：意见反馈表单后台、工单系统、在线客服。早期用短信与邮箱就够。

## 7. 验收

- [ ] 注册 → 进房，全程不需要问人
- [ ] 退出登录再登录，回到同一间房
- [ ] 新设备登录，旧设备被踢
- [ ] 改用户名立刻在对方界面生效
- [ ] 改密码后其他设备掉线
- [ ] 换手机号后房间、相册不变
- [ ] 用注册号发短信 → 收到临时密码 → 登录后强制改密码
- [ ] 非注册号发短信 → 不处理
- [ ] 注销 7 天内可撤销；执行后相册对对方仍可见
