# V3 · 聊天：发送与接收

> 只谈一件事：一条消息怎么发出去、怎么收到。
> 停、想聊、留、灰痕都不在这份里（见 `V3-B.md`、`V3-MEMORY.md`）。
> 属 PRD，不动前端。

---

## 1. 一条消息的一生

```
输入 → 按发送 → 本地立刻出现（发送中）→ 服务端接受（拿到 seq）→ 已发送
                        │
                        └─ 失败 → 自动重试 2 次 → 仍失败 → 「没发出去 · 重发」
```

### 1.1 四个状态

| 状态 | 用户看到 | 说明 |
|---|---|---|
| 发送中 | 气泡正常，右下角一个 40% 透明的小圆点，**不显示时间** | 先显示，不等服务端 |
| 已发送 | 小圆点消失，时间出现 | 时间用**服务端时间** |
| 失败 | 时间位置变 `没发出去 · 重发` | 气泡不消失、内容不丢 |
| 重发中 | 回到「发送中」 | 同一条，不复制 |

### 1.2 规则

- 按发送后**立刻清空输入框**，气泡马上出现；不等网络
- 发送失败**不弹窗**、不震动、不提示音
- 重发不产生第二条：同一条消息带同一个 `client_id`，服务端幂等
- 退出 App 再回来，没发出去的那条还在，可以重发
- 一条消息只有「发送中 / 已发送 / 失败」三种对外状态，**没有「已送达」「已读」**
- 已定：不做「已送达」。「发送中」只到服务器收下为止；对方什么时候收到，发送方永远不知道
- 对方离线、三天没打开，发送方看到的仍然是「已发送」——这是有意的，不是缺陷

## 2. 接收

```
对方发出 → 服务端分配 seq → WebSocket 推给我
   ├─ seq 正好接上 → 追加
   ├─ seq 有空洞 → 先 GET /messages?after_seq= 补拉，再接上
   └─ 重复 → 按 id 丢掉
```

- 排序只认**服务端 seq**，不认客户端时间
- 断线重连：先补拉，再接 WS；WS 事件带 seq，用来发现空洞
- App 在后台：收推送；打开后按 `after_seq` 补拉
- 从通知进入：滚到**那条消息**；如果它已经变短，滚到那一天那句

---

## 3. 顺序与时间

| 项 | 规则 |
|---|---|
| 排序 | 服务端 seq，单调递增，每房间一条线 |
| 显示时间 | 服务端 `created_at`，不用本机时钟 |
| 离线发送 | 以服务端**接受时间**为准（20:00 没网、20:30 发出，显示 20:30） |
| 时钟漂移 | 不校正、不提示；用户看到的永远是服务器那一套时间 |

为什么不用本机时间：两台手机的表可以差几分钟，甚至差到第二天；显示会打架，日期分隔会乱。

## 4. 三种内容

### 4.1 文字

- 2000 字上限；超出不能输入（不截断）
- 多行；最多显示 4 行输入框，超出内部滚动
- 纯文本，不解析链接、不识别电话

### 4.2 图片

- 一次一张，一条消息一张
- 选图 → 上传（预签名直传）→ 拿到 media_id → 再发消息
- 上传中：气泡里显示进度条；失败可重试，不重新选图
- 发送成功后：显示图 + 一行说明（时间 · 地点，如可得）

### 4.3 语音

- 按住录，上滑取消，松手发送；60 秒自动停
- 录完先上传，再发消息；上传失败保留录音，可重试
- 发送中同样是一个小圆点

## 4.4 引用与撤回

### 撤回

- 只有自己 2 分钟内的消息能撤回
- 点了就撤，不要二次确认
- 撤回后消息**完全消失**，对方侧淡出 120ms，不留「撤回了一条」
- 被引用过的那条撤回后，引用块显示 `原消息已撤回`，不显示内容

### 引用

- 长按任意一条 → `引用并回复`（和 `特别记忆` 并列）
- 输入框上方显示这条的**完整内容**；很长时视觉折叠，点「展开」看全文，**文字不截断**
- 发出去后，消息上方有一个引用块：完整内容（同样可展开）
- 点引用块跳到原消息
- 引用块**不显示原消息的时间**
- 只做一级引用：引用一条带引用的消息时，只引它本身，不套娃
- **引用不复制文字，只记 id，按原消息的当前状态实时渲染**：
  - 原文还在 → 显示全文
  - 第 7 天起：原消息删除 → 统一显示「10 月 9 日 · 已收进日历」，点了跳到那一天（短记 / 卡 / 点，有什么看什么）
  - 原文撤回 → 「原消息已撤回」
- 引用块永远带一个日期（10 月 9 日），不带时间；没有原文时，日期是唯一的线索
- **AI 压缩时不读引用块里的字**：引用只属于原消息所在的那一天，不能借引用复活旧话

**寿命**：压缩是「天」级的，不是「消息」级的。引用的原文只活 7 天——第 7 天那一天被压成短记、消息本身删除，引用就只剩日期和状态。引用不能比它指向的东西活得久。

为什么按 id 实时渲染：不是为了防谁，是为了**撤回能真的撤回**。如果引用是一份快照，原话撤回了、引用里还在，撤回就成了假的。

一句话原则：引用是「指着那一句说话」，不是「把那一句抄下来」。

### 不做

- 转发、多选、复制
- 嵌套引用（引用里的引用只保留直接那一层）
- 引用跨房间（没有第二个房间）
- 引用块里显示原消息的时间

## 5. 失败与边界

| 情况 | 行为 |
|---|---|
| 没网 | 标失败，不弹全局横幅；恢复后点重发 |
| 服务端 5xx / 超时 | 自动重试 2 次（2s、8s），之后标失败 |
| 重复提交 | 服务端按 `client_id` 去重，不产生第二条 |
| 发送太频繁 | 服务端限流（30 条/分钟）；超了提示 `一次说太多了`，草稿保留 |
| 房间已结束 | 输入区收起，不能发 |
| 对方还没进房 | 照常发；对方进来后补拉能看到 |

---

## 6. 通知

- 只推新消息；锁屏默认不显示内容
- 点通知进房间，滚到那条
- 多条新消息：不合并、不写「你错过了 N 条」
- 关掉通知：App 内照常到达，不丢消息

---

## 7. 不做

- 已读、已送达、正在输入（已定：都不做。没发出来的动作不署名，也不该变成信号）
- 复制、转发、多选（引用做，见 §4.4）
- 消息搜索
- 全局「网络异常」横幅
- 发送队列页面

---

## 8. 已定

| # | 项 | 决定 |
|---|---|---|
| 1 | 显示时间 | 服务器时间，不用本机时钟 |
| 2 | 离线消息时间 | 服务器接受时间（20:30 发出显示 20:30） |
| 3 | 单条字数上限 | 2000，超出不能输入，不截断 |
| 4 | 发送过快 | 30 条/分钟；提示「一次说太多了」，草稿保留 |
| 5 | 图片 | 一条一张，多张分多条发 |
| 6 | 连续消息合并 | **不做**：每条独立，各自带时间（保持设计稿原样） |
| 7 | 草稿 | 存本机，重启还在，发送后清掉 |
| 8 | 长消息折叠 | **不做**：完整显示，不折叠、不省略 |
| 9 | 链接识别 | **不做**：纯文本，不解析、不可点 |
| 10 | 语音入口 | **做**：输入框左侧加麦克风；设计稿没有，需补 |

## 9. 需要设计的改动

只有一处：**输入栏加语音入口**。

- 图片图标右侧、输入框左侧，加一个麦克风图标
- 点它切换「键盘 / 按住说话」；按住说话时整块变成一个大按钮，上滑取消
- 这是唯一需要改设计稿的地方；合并、折叠都不做
