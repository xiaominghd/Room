## 0. 一页纸

**是什么**
一个只属于两个人的私有通信空间：日常聊天、冲突时的暂停与调解、值得留下的共同日记。

**为谁**
一对长期关系、习惯文字沟通、对隐私敏感、愿意在冲突后修复的伴侣。v1 只服务这两个人，不面向第三方用户。

**解决什么**
1. 微信是公共广场，两个人的消息淹没在所有人的消息里；她只能把微信设成免打扰。
2. 聊天记录被永久化，每次争吵都留下可翻出的证据；关系需要遗忘的能力。
3. 冲突发生在对话里，调解却在对话之外；没有工具在冲突现场提供缓冲。
4. 通用 AI 有理解力但不在场；情侣 App 有仪式但没真实对话流。

**核心体验**
- 日常：一个安静、顺手、专属的主聊天，消息、图片、语音都在这里。
- 冲突：任一方按下暂停，对方同意后进入三轮调解室，AI 只发问、复述、交还。
- 记忆：聊天默认 7 天消散，只有被选择的内容进入共同日记。
- AI：不替你们说话，只在关键时刻踩刹车、翻译需要、递一个台阶。

**怎么算成功**
第 4 周时，双方每周至少有 5 天都主动发过消息；真实冲突里愿意用暂停；日记有内容；没有人因为 AI 关掉它。

**不做什么**
不做微信替代品（但要做你们两个人日常对话的第一选择）、不做社交、不做心理咨询、不做永久档案、不做监控与评分、v1 不做端到端加密。

## 1. 产品概述

### 1.1 一句话定位

**一个每天都想打开的、只属于两个人的房间：消息安静但不被淹没，对话允许被遗忘，吵起来时有一个不站队的 AI 帮你们踩刹车。**

### 1.2 背景与问题

1. **渠道没有优先级。**
   微信是公共广场：工作、家人、群、公众号全挤在一起。她把微信设成免打扰是理性的——不是不在乎，而是这个渠道里没有「只属于我们」的位置。要解决的不是音量，而是渠道本身的专属性和优先级。

2. **聊天被永久化。**
   所有对话都变成可以随时翻出的档案，每一次争吵都留下证据。关系需要遗忘的能力，而现在没有工具提供它。

3. **冲突发生在对话里，调解却在对话之外。**
   心理咨询要预约，吵架是即时的；现有聊天工具没有一个在冲突现场提供缓冲。

4. **AI 有理解力，但不在场。**
   通用助手不知道你们的前情、内梗和昨天为什么冷战；情侣 App 只有打卡和测试，没有真实的对话流。

**空位：** 把「关系中最难的那部分沟通」放进一个私有、可遗忘、有第三方在场的地方。

### 1.3 目标用户与情境

- **用户**：两个人，长期关系，习惯文字沟通，愿意在冲突后修复，对隐私敏感。
- **情境（按频率排序）**：
  1. 日常碎片时间：分享、废话、晚安。
  2. 冲突升级时：需要停一下。
  3. 事后冷静期：需要修复。
  4. 长期：想留下点什么。
- **不服务**：单身用户、多人关系、群聊、公开分享、工作沟通。
- **产品属性**：v1 是为这两个人做的自用工具，不面向第三方用户。
- **与微信的关系**：这个 App 承载你们两个人之间的日常对话、冲突与记忆；微信只留工作、家人和群。替代的不是整个微信，是「我们俩」那一段。

### 1.4 核心价值（排序）

1. **被陪伴（第一价值）**
   一个每天都想打开的地方——专属、安静、没有噪音。日常的分享、废话、晚安都有地方可去，消息不会被淹没在别人的对话里。

2. **被保护（差异化）**
   冲突升级时，AI 请求暂停，调解室只发问、不评判；事后还有一次修复的邀请。平时不打扰，关键时刻靠得住。

3. **被记住（长期价值）**
   聊天默认 7 天消散，只有被你们选择的内容进入共同日记。

4. **被看见（支撑原则）**
   专属通知身份，但不越界——尊重她的系统免打扰，绝不偷偷突破。

### 1.4.1 日常价值从哪里来（v1 的生死线）

v1 不假设「比微信更好用」——功能、速度、网络效应都赢不了。v1 只承诺一件事：**这条通道比微信更「属于我们」**。日常价值由四件具体的事构成，全部是减法：

1. **打开即输入**：冷启动到输入框不超过一次点击；没有首页、没有列表、没有「发现」。
2. **通知属于我们**：独立通知渠道与提示音，不会被工作群和公众号淹没；也不绕过系统免打扰。
3. **没有观众**：没有群、没有第三人、没有公开可见的痕迹；v1 不做端到端加密，但只有两个人进得来。
4. **会消散**：日常废话不必背负「永久记录」的重量——这是微信给不了的放松。

**取舍（v1 明确）**：v1 不承担「有意思」。仪式、回顾、纪念日都不是本版本目标，判断标准只回到「好不好用、烦不烦」两条。如果第 4 周留存不成立，优先补「轻回顾」（v1.1），而不是往聊天流里加功能。

**验收方式**：不看功能数，看第 2 周后双方在「想分享一件小事」时是否先想到它；唯一硬指标仍是每周双方都有消息的天数 ≥ 5。

### 1.5 愿景

- **v1**：一个顺手、安静的日常聊天空间（文字 / 图片 / 语音）+ 主动遗忘 + 手动调解 + 共同日记。
- **之后**：更克制的冲突识别（默认关闭）、修复仪式、周回顾，以及可接入更多 Agent 的关系空间。
- **长期**：成为你们关系里唯一一个「我们共同的第三方」——不夺走沟通，只让沟通发生得更容易。

### 1.6 非目标

- **不做全场景 IM**：不承载工作、家人、群聊；但要做你们两个人日常对话的第一选择。
- **不做社交**：没有群、没有第三人、没有公开分享。
- **不做心理咨询**：不诊断、不治疗、不评判对错；遇到危险信号立即停止，按 6.5 的安全路径处理（求助只给当事人，不在双方可见的位置提示）。
- **不做永久档案**：聊天不是证据库，日记才是记忆。
- **不做监控与评分**：不统计谁对谁错、谁回得快、谁更爱谁。
- **v1 不做端到端加密**：AI 需要读上下文；用 TLS、自托管和短期留存来缓解，并在产品内明示。
- **v1 不做每日一问、纪念日、共享空间等日常仪式**：陪伴由聊天本身和日记承担；v1 明确不承担「好玩」，「有意思」不是本版本的验收维度（见 1.4.1）。

### 1.7 电梯演讲

> 我们在微信里聊天，但微信是公共广场：她的消息被免打扰淹没，聊天记录永久保存，吵架时没有人踩刹车。这个小房间只属于我们：消息会消散，值得的进入日记；当对话开始伤人，一个不站队的 AI 会请求暂停，带我们各说一句真正想说的话。它不替我们说话，只让我们说得出口。

### 1.8 关键假设（按优先级）

1. **你们愿意把日常对话的一部分从微信搬过来**，而不是只在吵架时想起它。这是 v1 的生死线。
2. 专属通道能让她愿意多打开一个 App，而不是继续留在微信。
3. 冲突当下，双方愿意按下「暂停」。
4. AI 的复述准确率足够高（无修正率 ≥ 70%）。
5. 「聊天会消散」让关系更轻松，而不是更焦虑。
6. 日记能提供持续回访的理由，而不只是新鲜感。
7. **到期提醒的频率不构成新的打扰**：7 天窗口下，每天到期的消息量与提醒次数在可接受范围内。如果每天都要处理一次「要留点什么吗」，提醒本身就会变成噪音——这条必须真机验证，而不是假设。

## 2. 用户与场景

### 2.1 两个人，两种视角

- **发起者（你）**：技术型，愿意折腾，负责部署和维护；对产品有明确期待。
- **被邀请者（她）**：普通微信用户，判断标准只有三个——好不好用、烦不烦、有没有意思。注意：「好不好用」包含「不用配置」——任何需要手填服务器地址、端口、证书的步骤都算失败。
- **共同点**：希望被理解；对「被监控」敏感；讨厌吵架后的冷战。
- **关键差异**：你能忍受一个不完善的产品，她不会。v1 的体验标准按她来定。

### 2.2 三条场景线

#### 场景一：日常（最高频，决定产品生死）

- **触发**：想分享一件小事、一张照片、一句废话；睡前想说晚安。
- **路径**：打开 App → 发文字 / 图片 / 语音 → 对方收到专属通知 → 回复。
- **成功**：比微信安静、顺手、有「只属于我们」的感觉。
- **失败**：通知延迟、图片糊、语音卡、输入法遮挡——任何一项都会让人退回微信。

#### 场景二：冲突（差异化，决定产品价值）

- **触发**：一句话被误解 → 语气升级 → 互相伤害。
- **路径**：任一方点暂停 → 对方接受 → 调解室三轮 → 双方确认结果 → 回到聊天。
- **成功**：双方都觉得被听见；没有产生新的伤害；愿意下次再用。
- **失败**：AI 站队、误判、说教；一方拒绝；暂停卡本身变成新的争吵点。

#### 场景三：修复与记忆（长期，决定留存）

- **触发**：冲突次日；或一个值得留下的瞬间。
- **路径**：收到修复提醒 → 各说一句 → 可选存日记；或主动把聊天片段整理成日记。
- **成功**：日记成为回访理由；遗忘不带来焦虑。

### 2.3 首月旅程

- **第一次**：点开邀请链接（服务器地址已内嵌）→ 安装 → 邀请码自动带入 → 设置昵称、头像 → 第一条消息 → 第一次收到「专属」通知。全程不出现「服务器地址」输入框，除非主动展开「高级设置」。
- **第一周**：日常使用 → 第一次到期提醒 → 第一次存日记 → 第一次冲突 / 暂停。
- **第一个月**：形成习惯 → 调解被真实使用 → 日记有内容 → 决定是否把日常聊天彻底搬过来。

### 2.4 关键失败模式

| 失败模式 | 表现 | 对策方向 |
|---|---|---|
| 只装不用 | 一周后回到微信 | 日常体验优先、她来验收 |
| 只在吵架时用 | 平时冷清，冲突时才打开 | 日记与日常聊天价值 |
| AI 误判被关闭 | 一次误报后再也不开 | v1 不做自动检测、手动发起 |
| 遗忘引发焦虑 | 想找的对话已经没了 | 24h 提醒、保留期可调 |
| 暂停卡成为新矛盾 | 「你为什么按暂停」 | 请求式、双方同意、中性文案 |

## 3. 产品原则

原则不是口号，是后面所有取舍的裁决依据。每条配 Do / Don't。

### 3.1 日常优先

- **Do**：聊天页打开即用，发消息不超过两步；图片、语音发送不打断对话；通知必须可靠。
- **Don't**：为了 AI 功能增加聊天复杂度；在聊天流里塞任务、卡片、运营内容。

### 3.2 专属，但不越界

- **Do**：独立通知身份、自定义提示音、清楚的系统设置指引。
- **Don't**：绕过系统勿扰；用红点、连续提醒、焦虑感驱动打开。

### 3.3 对话会消散，日记会留下

- **Do**：默认 7 天、到期前 24 小时提醒、只保存被选择的内容。
- **Don't**：提供回收站或变相永久备份；默认替用户收藏；把「遗忘」做成需要不断确认的负担。
- **日记不是新的证据库**：从聊天存入日记的内容，对方可见，标注保存者与来源消息；默认中性叙述，不以单方第一人称把一段对话固化成「我的版本」。存日记是共享动作，不是取证动作。

### 3.4 AI 是共同资产

- **Do**：调解与总结双方可见；双方都能发起、都能关闭；AI 的存在对两个人透明。
- **Don't**：私密顾问、单方军师、暗中分析对方；任何「只有你知道」的 AI 结论。
- **两类 AI 不要混为一谈**：调解 AI 对「房间」说话，产出面向双方的复述与确认；日记 AI 只是保存者的笔，产出必须署名、可编辑、默认中性。前者禁止单方视角，后者允许「我的视角」但必须标注，且对方可见。

### 3.5 人类主导

- **Do**：AI 只发问、复述、确认、交还；所有 AI 产出都要人确认；AI 缺席时流程照常。
- **Don't**：自动发送、替人表态、判断对错、给关系打分。

### 3.6 克制优先

- **Do**：v1 只做手动暂停；自动检测默认关闭；功能少而稳，宁可漏不可错。
- **Don't**：用「智能」堆功能；在冲突现场刷存在感；把「陪伴」做成打扰。

### 3.7 安全优先于「不评判」

- **Do**：出现人身安全信号（暴力或伤害威胁、自伤 / 自杀迹象、跟踪、控制与隔离）时，立即结束调解；把求助信息**只给当事人**，不放进共享聊天流；不解释触发原因，不留痕。
- **Don't**：把安全提示做成双方可见的横幅（施害者也会看到）；用「各打五十大板」的调和语气处理威胁；在危险情境里继续追问「你希望对方下次怎么做」。

安全是唯一可以打破「双方可见、人类主导、克制」三条原则的例外。这条例外必须写进产品，而不是留给模型临场判断；同时要接受它的代价：**误停一次可以，但绝不能因为误判而把求助暴露给另一个人**。

## 4. 功能需求

### 4.1 账号与接入

**目的**：两个人能安全地进入同一个私有空间，且只有你们能进入。

| ID | 需求 | 说明 / 验收 | 优先级 |
|---|---|---|---|
| F-A01 | 邀请制注册 | 服务端生成一次性邀请链接 / 二维码，**内含服务器地址与邀请码**，注册后失效；账号上限 2 个；无公开注册；链接过期或已使用时给出中性提示与「再要一个邀请」 | P0 |
| F-A02 | 密码登录 | 用户名 + 密码；scrypt 哈希；JWT 90 天；`token_version` 支持全端登出 | P0 |
| F-A03 | 密码恢复 | 注册时生成一次性恢复码，用户自行保存；忘记密码用恢复码重置，不依赖邮箱 | P0 |
| F-A04 | 首次引导 | 打开邀请链接 → 服务器地址已内嵌（默认折叠，仅在「高级设置」可改）→ 邀请码自动带入 → 用户名、密码、昵称、头像（可选）；全程不要求手填地址或端口 | P0 |
| F-A05 | 多设备 | 允许多设备登录；v1 只保证一台手机的体验；推送 token 按设备记录 | P1 |
| F-A06 | 个人资料 | 修改昵称、头像、密码；重新生成恢复码 | P1 |
| F-A07 | 邀请落地页 | `https://<域名>/invite/:code` 提供 APK 下载与深链唤起（App Link 优先，自定义 scheme 兜底）；链接不暴露邀请码给第三方页面 | P0 |

**不做（v1）**：公开注册、邮箱/手机号找回、账号注销与数据导出（v1.1）。

### 4.2 聊天

**目的**：一个顺手、安静、可靠的日常主聊天。

| ID | 需求 | 说明 / 验收 | 优先级 |
|---|---|---|---|
| F-C01 | 文字消息 | 支持多行、emoji；发送失败可重试 | P0 |

## 5. 核心流程与状态机

### 5.1 消息生命周期

```
created ──► delivered ──► expired ──► purged
   │            │
   └─ 2min 内 ──┴──► recalled（墓碑行，随 TTL 消散）
```

- 发送：客户端生成 `client_msg_id`，乐观展示「发送中」；服务端幂等去重，成功后广播。
- 送达：接收方在线经 WS 接收；离线则在下次连接或打开时按 `after=seq` 补拉。
- 撤回：服务端校验 2 分钟窗口；删除原文与媒体；广播墓碑事件。
- 过期：清理任务删除过期消息；引用置空；媒体无引用则删除。

### 5.2 暂停 / 调解状态机

```
idle
 └─ pause.request ─► pending（2 分钟）
      ├─ accepted ─► mediation.active
      │    ├─ 完成 ─► completed（生成待双方确认的 outcome_note）
      │    ├─ 离开 ─► paused（30 分钟内可恢复）
      │    ├─ 安全信号 ─► safety_halt（立即结束；不生成 outcome_note；不推送）
      │    └─ 30 分钟无活动 ─► abandoned
      ├─ declined ─► idle（不指责、不追问）
      └─ expired ─► idle
```

- 调解轮次：开场 → 第 1 轮 → 第 2 轮（复述确认）→ 第 3 轮 → 总结 → 可选修复轮。
- 每轮 3 分钟超时，可跳过；30 分钟无活动自动结束。
- 安全信号凌驾于流程：一旦触发，跳过总结、跳过 `outcome_note`、跳过次日修复提醒；共享层只留中性结束语，求助只走私密通道。

### 5.3 遗忘任务

```
每小时：扫描 24h 内到期消息 ─► 若该批未提醒 ─► 系统消息 + 低优先级推送
每 10 分钟：删除过期消息 ─► 清理无引用媒体 ─► reply_to_id 置空
每天：清理 30 天前的 outcome_note / agent_runs / 日志轮转
```

### 5.4 日记草稿

```
选中消息 ─► 构造上下文 ─► AI 草稿（默认中性；可切「我的视角」） ─► 人工编辑 ─► 保存（标注来源与保存者）
                     └─ AI 失败 ─► 原文复制到草稿 ─► 人工编辑
```

### 5.5 通知触达

```
事件 ─► 前台判断（抑制） ─► 推送 ─► 点击深链到会话 / 调解室 / 日记
```

## 6. 数据与隐私

### 6.1 数据分类与生命周期

| 数据 | 存放 | 保留 | 谁能看 | 删除方式 |
|---|---|---|---|---|
| 账号、密码哈希 | SQLite | 永久 | 服务端 | 账号删除（v1.1） |
| 聊天消息 | SQLite | 7 天（1–30 可调） | 双方 | 到期自动 / 撤回 |
| 聊天媒体 | 磁盘 | 随消息 | 双方（鉴权） | 到期自动 / 撤回 |
| 调解记录 | SQLite | 随聊天 TTL | 双方 | 到期自动 |
| 安全事件（`safety_halt` + 规则 ID） | SQLite | 30 天 | 服务端审计 | 自动清理，不含原话 |
| `outcome_note` | SQLite | 30 天 | 双方 | 到期 / 手动 / 存日记 |
| 日记（含来源与署名） | SQLite + 磁盘 | 永久 | 双方 | 手动删除 |
| AI 调用摘要 | `agent_runs` | 30 天 | 服务端审计 | 自动清理 |
| 推送 token | SQLite | 直到登出 / 失效 | 服务端 | 登出删除 |
| 服务日志 | 文件 | 14 天 | 服务端 | 轮转 |

### 6.2 AI 数据边界

- 只发送必要上下文：调解室内的消息；日记草稿选中的消息。
- 不发送：全量历史、日记全文、账号信息、未选中的消息。
- 供应商默认 DeepSeek；上线前确认其 API 条款不用于训练，否则切换通道或本地模型。
- Prompt 中使用昵称，不带真实姓名、手机号等无关个人信息。
- AI 输出只记入 `agent_runs`（30 天，用于调试与成本），不进入聊天记录。
- 调解与日记草稿的 AI 开关独立；任一方关闭即生效。

### 6.3 知情同意

- 首次启动一页说明：AI 读什么、何时读、发给谁、留多久；双方都同意后才启用 AI 功能。
- 进入调解室前提示「AI 将参与本房间」。
- 设置页明示：锁屏预览会显示消息内容，以及由此带来的隐私风险。
- 双方都能随时关闭调解 AI 与日记 AI。

### 6.4 安全底线

- TLS（Caddy 自动证书）。
- scrypt 密码哈希；JWT 90 天 + `token_version`。
- 邀请码注册，最多 2 个账号；无公开注册。
- 登录限频；媒体访问鉴权；上传类型与大小限制（图片 ≤10MB，语音 ≤5MB）。
- 每日备份 SQLite + 媒体到服务器本地目录，权限 600；恢复步骤写入 README。
- **不做端到端加密**：AI 需要读上下文；用 TLS、自托管、7 天消散和最小化数据来缓解，并在产品内明示。

### 6.5 安全与求助边界

- **判定分两层**：规则层（高危词与模式，召回优先、宁可误停）与模型层（补充识别，不单独决定终止）。规则命中即停，不向用户解释命中了什么。
- **告知分两层**：共享层只有中性结束语「这次先到这里」；私密层只给当事人看求助卡片（先离开、联系信任的人、当地紧急服务 / 心理援助 / 反家暴热线）。
- **留痕最小化**：安全触发不进聊天记录、不进日记、不进 `outcome_note`；服务端只保留 `safety_halt` 事件与规则 ID（30 天），不含原话，避免二次暴露。
- **不承诺、不诊断**：不做治疗性承诺、不给关系结论；文案只说「现在不适合继续」，不说「你有危险」。
- **资源可配置**：号码与链接由部署者在环境变量 / 配置文件中维护（随地区变化），产品内不硬编码，避免过期或错误。
- **误报的代价**：误停一次调解是可接受的；误报后的修复是「下次照常可以发起」，不弹道歉、不解释系统。

## 8. 指标与验收

### 8.1 北极星指标

**双方每周互动的天数**：同一天双方都至少发送过一条消息（不区分主动发起或回复）。

- 第 4 周目标：≥ 5 天 / 周。
- 解释：直接衡量「日常主聊天」是否成立；不给单方刷屏留空间。

### 8.2 支撑指标

- 日均消息数；图片 / 语音占比。
- 日记条目数 / 周；到期提醒后的保存率。
- 暂停请求接受率 ≥ 40%；调解室完成率 ≥ 60%。
- AI 复述无修正率 ≥ 70%。
- 推送送达率；崩溃率；消息发送失败率。

### 8.3 护栏指标

- 通知关闭率、AI 关闭率、调解功能关闭率。
- 单方消息占比（防止一方唱独角戏）。
- 撤回后被追问的次数。
- 因「误判 / 被打扰」而关闭调解的次数。

### 8.4 测量方式

- 服务端事件统计，不接第三方分析 SDK。
- 发起者可查看只读的 `/admin/metrics` 页面或导出周报。
- 不做个人行为排行榜，不统计「谁更爱谁」。

### 8.5 v1 验收清单

- [ ] 两台 Android 真机：文字 / 图片 / 语音、引用、撤回、未读角标正常。
- [ ] 邀请链接一次装好：不出现服务器地址输入，邀请码自动带入，过期 / 已用链接有中性提示。
- [ ] 温和模式：无已读、无实时在线、输入中正常。
- [ ] 断网重连不丢不重；消息幂等。
- [ ] 7 天到期清除 + 24 小时前提醒 + 存日记；日记跨过期保留。
- [ ] 7 天窗口下的到期提醒频率实测：连续 3 天不出现「每天都要处理一次」的骚扰感。
- [ ] 暂停需双方同意；拒绝 / 超时正常；调解三轮可走完；AI 不可用时静态台词可用。
- [ ] 安全演练：模拟自伤 / 暴力词 → 共享流只有「这次先到这里」，双方各自只看到自己的私密求助卡片，聊天记录 / 日记 / `outcome_note` 均无痕。
- [ ] 日记来源：从聊天生成 → 默认中性、可切「我的视角」并标注、保存后聊天流出现系统消息、来源与编辑痕迹正确。
- [ ] 次日修复提醒到达；`outcome_note` 双方确认。
- [ ] 通知独立渠道、显示昵称 + 内容、前台抑制、勿扰不被绕过。
- [ ] Docker 一键部署、HTTPS 正常、备份可恢复。
- [ ] 服务端测试通过（幂等、TTL、暂停 / 调解状态机、Prompt 构造）。

## 12. 附录

### A. 调解剧本全文

**暂停卡（系统卡片，双方可见）**

> 想先停一下，可以吗？
> `[一起停一下]` `[继续]`

**调解室**

> **开场**：这里没有对错，也不会有结论。每人说一句就好。

> **第 1 轮**：刚才最让你难受的是哪一句话？（双方各答一句，轮流）

> **第 2 轮（复述）**：我听到的是——A 觉得……；B 觉得……。有说错吗？（允许修正；双方都纠正时：是我理解错了，你们直接说吧。）

> **第 3 轮**：你希望对方下次怎么做？每人一句。

> **收尾**：我记下两件事：……。接下来交给你们，想回来随时叫我。

> **可选修复轮**：要不要各自说一句，自己哪里说得重了？

> **次日修复提醒**：昨晚有两句话可能还卡着。要不要各用一句话，说说自己哪里说得重了？

> **关系冲突收尾（共享，双方可见）**：这次先到这里。等你们都想说话的时候，再回来。

> **人身安全（私密，各自只看到自己的）**：现在不适合继续。如果你感到不安全：先离开这个对话，去一个有其他人的地方；联系你信任的人，或当地紧急服务 / 心理援助 / 反家暴热线。这个提示不会出现在聊天记录里，对方看不到。

> **禁止出现**：任何「检测到冲突」「安全协议已触发」「你需要求助」的共享文案，以及任何可能让对方推断出「是她触发的」的痕迹。

### B. Prompt 原则

1. **角色**：中立沟通调解员，不是心理咨询师，不是法官。
2. **对象**：只对「房间」说话，永远不私聊任何一方。
3. **动作**：只发问、复述、请求确认、交还；不替任何一方表态。
4. **复述**：必须引用原话片段；最多两句；以「我听到的是……，对吗？」结尾；双方都纠正时立即放弃。
5. **语气**：温暖、平实、低姿态；用「好像」「要不要」「我听到」；不用「冷静」「别生气」「你应该」「检测到冲突」「你们需要」。
6. **禁止**：判断对错、分析人格、预测关系、给建议清单、诊断心理问题。
7. **长度**：每次发言不超过两句；不写小作文。
8. **安全**：出现威胁、羞辱或自伤迹象，立即停止调解；共享层只给中性结束语，求助走各自私密的通道（见 3.7 / 6.5）。
9. **降级**：AI 超时或失败时，使用静态台词，流程照常。
10. **隐私**：只使用本轮上下文，不引用未选中的历史。

### C. 术语

| 术语 | 定义 |
|---|---|
| 消散（TTL） | 聊天消息在保留期结束后自动删除 |
| 暂停（Pause） | 任一方发起的「先停一下」请求 |
| 调解室 | 双方同意后进入的结构化对话空间 |
| `outcome_note` | 调解结束时双方确认的简短结果 |
| 共同资产 | AI 属于这段关系，双方可见、可关闭 |
| 温和模式 | 无已读回执、保留输入中、只显示最近活跃 |
| 日常主聊天 | 两个人之间的日常对话主要发生在这个 App |

### D. 竞品参考

| 类别 | 代表 | 它有什么 | 它缺什么 |
|---|---|---|---|
| 公共 IM | 微信 | 普及、可靠、功能全 | 渠道噪音、记录永久化、无调解 |
| 情侣 App | Paired / Between 等 | 打卡、问答、纪念日 | 没有真实对话流，AI 不在场 |
| 通用 AI | ChatGPT / DeepSeek | 理解力强 | 没有你们的上下文，不在对话现场 |
| 本产品 | — | 专属通道 + 主动遗忘 + 在场上场调解 + 共同日记 | 需验证日常是否会真的搬过来 |

### E. 关键决策记录

| 决策 | 结论 | 理由 |
|---|---|---|
| 产品价值排序 | 陪伴 > 保护 > 记住 | 日常使用是地基；没有日常，调解不会发生 |
| 与微信的关系 | 两个人的日常主聊天 | 陪伴优先要求高频使用；只替代「我们俩」那一段 |
| 日常仪式 | 只做聊天 + 日记 | 保持克制，不做打卡和任务 |
| 已读 / 在线 / 输入中 | 温和模式 | 避免「已读不回」压力，保留正向的输入中 |
| 撤回 | 2 分钟内 | 给冲动发言留退路，符合「话会消散」 |
| 日记可见性 | 全部共享 | 共同日记的定位，避免新的信息不对称 |
| 锁屏通知 | 显示昵称 + 内容 | 日常便利优先；设置页提示隐私风险 |
| 调解触发 | 手动发起，双方同意 | 误判成本高；宁可漏不可错 |
| 聊天保留 | 默认 7 天，可调 1–30 | 主动遗忘；24 小时提醒作为安全网 |
| 平台 | Android 优先 | 两人都用安卓；跳过 iOS 证书与审核 |
| 端到端加密 | v1 不做 | AI 需要读上下文；用 TLS + 自托管 + 短期留存缓解 |
| 自动检测 | v1 不做 | 避免误报摧毁信任；后续默认关闭 |
| 安全与求助 | 双路径：共享只给中性收尾，求助只给当事人 | 安全优先于「双方可见」；提示本身被发现会加重危险 |
| 日记叙述 | 默认中性第三人称，「我的视角」需标注 | 防止单方把一段对话固化成永久的「我的版本」 |
| 邀请接入 | 链接内嵌服务器地址，不手填 | 她的「好不好用」包含「不用配置」；手填地址即流失 |
| 「有意思」 | v1 不承担；轻回顾进 v1.1 | 日常留存不成立时才补，避免范围膨胀 |
| 北极星 | 双方每周互动天数 | 直接衡量日常主聊天；防单方刷屏 |
