# 工作约定

> 2026-11-16 定。之后每次动产品/代码前先过一遍这五条。

1. **不换大框架。**
   单实例、单房间的结构已经定了。V3 只做细节打磨；要动架构（多租户、换数据库、换端），必须先单独立项，写清代价，再决定。

2. **用户好用优先于技术完备。**
   同一件事有两条路时，选用户少一步、少一个概念的那条。技术债记下来，不挡路；但别用「以后不好扩」当理由，让用户多点两次。

3. **这一轮只谈 PRD，不动前端。**
   `demo/` 与 `app/` 的界面和代码这轮不改。设计变更另开一轮，确认后一起改。

4. **每次改动先问三句：**
   这是打磨还是换框架？用户会少一步还是多一步？会不会让已经做好的东西重做？

5. **文档是唯一事实源。**
   讨论结论写进 `docs/`，不留在聊天里。下次接手只看文档。
