# 屏幕元素结构 · UI 设计交接

> 给做视觉设计的人或 AI。
> 本文只定：**有哪些屏、每屏有哪些区块、区块里有什么、有哪些状态、文案是什么、跳到哪**。
> 不含：颜色、字体、字号、间距、圆角、阴影、图标风格、动效时长——这些归设计方。
> 依据：`docs/PRD-v4.md`（v4.1）。文案一律照抄，不要改写。

---

## 0. 怎么用这份文档（设计方先读这 6 条）

1. **屏 id 就是设计稿的命名**（`room`、`day-card`…），不要另起名字。
2. 每个 id 必须交：**正常态 +「状态」里列出的全部变体**。缺变体算没交。
3. 界面文案用这里给的中文原样；不要改写、不要用 lorem ipsum、不要加感叹号。少数空态/错误文案 PRD 没写、是本文补的（见附录 A），可以用，但要短、要像系统说的话。
4. **不要补产品逻辑**。文档写「没有」的，就是没有；写「不出现」的，一个像素都别加。
5. 一屏只有一个主操作。次要操作放低一级，危险操作放最后。
6. 拿不准就回来问，不要自己发明第 7 条状态。

## 1. 硬约束（产品层，设计不能改）

| 约束 | 说明 |
|---|---|
| 没有 Tab 栏 | 房间是根；相册、我的都从房间进，返回都回房间 |
| 没有会话列表、没有联系人 | 打开就是这一个人的房间 |
| 没有头像 | 包括「我的」「个人资料」 |
| 没有已读、送达、在线、正在输入 | 一个都不要画 |
| 没有角标 | 图标上不出现数字 |
| 一级页只有 5 个 | 启动、登录、注册、开房码页、房间 |
| 弹层不叠弹层 | 同一时间最多一层；确认类关闭后回来源页 |
| 机器做的要标出来 | AI 问的那句标「AI」；图文卡标「AI 整理」 |
| 人没做的不要说 | 没回、没按、没来，界面上不出现任何提示 |
| 房间的原文只留 28 天 | 到期变成一行日期，不是灰掉、不是折叠 |
| 相册不能删 | 只能「从我这边隐藏」；例外只有自己的此刻、自己标的特别记忆 |

## 2. 全局结构规范

### 2.1 每屏的三段骨架

| 段 | 内容 | 规则 |
|---|---|---|
| 顶部 | 返回（二级页才有）/ 标题 / 右侧动作 | 右侧动作最多 1 个；一级页不给返回 |
| 中部 | 内容区 | 可滚动；空态、错误态占同一位置 |
| 底部 | 主操作（有的屏才有）/ 安全区 | 键盘弹起时主操作跟随上移或滚入视野 |

**画板**：一套稿只用一个尺寸（建议 Android 主流 360×800 或 412×915，选一个），全文档统一，不要混用。

### 2.2 四种非常规状态，每屏都要有

| 状态 | 表现 |
|---|---|
| 加载 | 页内一行「加载中」，不整屏遮挡、不转圈盖住内容 |
| 空 | 每屏自己的一句话（见各屏「文案」） |
| 错误 | 页内错误行 + 重试；不弹窗 |
| 离线 | 不弹全局横幅；已读内容可看，写操作标失败可重试 |

### 2.3 必须能区分的五级语义

视觉你定，但这五级必须一眼分得开：

1. **主操作**（一屏只有一个）
2. **次级操作**
3. **危险操作**（不可逆的：留、删、注销、退出）
4. **弱说明**（解释、脚注、时间）
5. **机器标注**（「AI」「AI 整理」——必须和人的话视觉不同）

### 2.4 滚动与键盘

- 消息流上翻历史时，新消息**不拽回底部**；只在底部给一个「一个点 + 新消息」的提示，不显示条数。
- 消息不超过一屏时，整块垂直居中偏上，**不要贴底**。
- 输入区固定在底部，键盘弹起时整体上移。

### 2.5 覆盖层与弹层（不是新页面）

| 类型 | 用于 | 行为 |
|---|---|---|
| 覆盖层 | 房间的半关、关门 | 盖在当前页上，房间变暗，不换路由 |
| 弹层 | 长按菜单、看图、各类确认 | 最多一层；点遮罩 = 取消（留一天、删小框的确认除外，见各屏） |

## 4. 准入

### A1 `launch` 启动

**用途**：判断会话、深链、通知，决定送往哪。它是品牌页，不是加载页。

**结构**（垂直居中，单列）
1. 品牌区：应用标识 + 字标「房间」
2. 一句话定位（弱说明，一行）
3. 状态行（条件）：`正在检查`
4. 错误块（条件）：一行错误 + 重试
5. 版本过低块（条件）：说明 + 去更新
6. 取消前往（条件，有深链/通知目标时）：一行文字操作

**状态**
| 状态 | 行为 |
|---|---|
| 检查中 | 只显示品牌区 + 状态行 |
| 未登录 | → `login` |
| 已登录有房 | → `room`（门有状态就带状态） |
| 深链 | → `invite-landing`；未登录先 `login`/`register`，房间 ID 不能丢 |
| 通知 | 按目标落到 消息 / 一天的卡 |
| 网络不可用 / 服务端不可达 / 登录态失效 | 错误块 + 重试 |
| 版本过低 | 只能去更新 |

**文案**：`房间`、`正在检查`、`重试`、`版本过低，去更新`、`取消前往`
**禁忌**：不要 sologan 以外的营销文案、不要进度条、不要「欢迎回来」。

---

### A2 `invite-h5` 邀请落地（站外网页）

**用途**：没装 App 的人的第一屏。告知 + 下载 + 把房间 ID 带过去。**不注册、不填表、不在网页里输码。**

**结构**
1. 应用标识
2. 标题
3. 说明（两行）
4. 已带 ID 的提示（一行）
5. 主操作：去下载；次操作：已装，打开
6. 脚注：一间房只有两个位置

**状态**：有效 / 过期 / 已用 / 满员 / 缺房间 ID / 内置浏览器拦截（给「用浏览器打开」）

**文案**：`有人给你留了一个房间`、`这个房间只住两个人`、`房间 ID 已带上，装好直接进`、`去下载`、`已装，打开`、`一间房只有两个位置`、`用浏览器打开`

---

### A3 `login` 登录

**用途**：手机号 + 密码。用户名不能登录。

**结构**
1. 标题（二级页规格的页标题）
2. 输入：手机号
3. 输入：密码
4. 主操作：登录
5. 错误行（条件，统一一句）
6. 次要入口：注册 / 忘记密码（同一行，分开两边）
7. 说明行：单设备，新登录踢旧

**状态**：空 / 输入中 / 手机号或密码不对 / 限流（5 次/小时）/ 网络失败 / 临时密码登录（成功后直接进强制改密）/ 被踢下线（回来时给一句说明）

**文案**：`手机号`、`密码`、`登录`、`手机号或密码不对`、`没有账号，注册`、`忘记密码`、`一台设备登录；新登录会让旧设备退出`

**禁忌**：不要「用户名」输入、不要第三方登录、不要「记住我」、不要验证码。

---

### A4 `register` 注册

**结构**
1. 标题
2. 输入：手机号
3. 输入：再次输入手机号
4. 输入：用户名
5. 输入：密码
6. 说明块（三行）：手机号是编号 / 用户名是房间里显示的名字 / 不发验证码、不收证件
7. 协议勾选（用户协议 / 隐私政策，可点）
8. 主操作：注册
9. 次要入口：已有账号去登录

**状态**：格式错 / 两次不一致 / 手机号已注册 / 用户名重复 / 密码不足 8 位 / 网络失败 / 成功

> 成功后去向有两种（没邀请 → 建房进房间；从邀请链接来 → 输码页），**界面上不用区分，但你不用设计分支**。

**文案**：`手机号`、`再次输入手机号`、`用户名`、`密码`（至少 8 位）、`手机号是你的编号，用户名是房间里显示的名字`、`不发验证码，不收证件`、`我已阅读并同意《用户协议》和《隐私政策》`、`注册`、`已有账号，去登录`

---

### A5 `forgot-password` 忘记密码说明

**用途**：讲清楚没有自助找回，只有人工。**这屏不填表、不发请求。**

**结构**
1. 标题
2. 说明（两行）：没有自助找回
3. 步骤（3 步，编号）：发短信 → 人工核对 → 收到临时密码
4. 运营者号码（大字，可拨）
5. 短信内容原文块（引用样式）
6. 临时密码规则（三行：8 位 / 24 小时 / 用一次 / 登录后要改）
7. 边界说明：不是这个号码发来的不处理
8. 时效说明：不是实时，通常 24 小时内
9. 回登录

**状态**：默认 / 已记下号码 / 运营者号码未配置（整块不可用，说明一行）/ 找不回（注册号换了或卡丢了）

**文案**：`找回密码`、`没有自助找回`、`用注册手机号发短信到这个号码`、`内容写`、`找回密码`、`8 位，24 小时有效，用一次，登录后要改密码`、`不是这个号码发来的，不处理`、`不是实时，通常 24 小时内`、`回登录`

**禁忌**：不要「输入手机号获取验证码」、不要进度环、不要倒计时。

---

### A6 `invite-landing` 开房码页

**用途**：第二个人在 App 内的一屏。房间 ID 由链接带入，只输 6 位码。

**结构**
1. 房间 ID（只读，等宽感的大字，如 `R7K2M9`）
2. 房主用户名（弱说明：谁给你留的）
3. 6 位码输入（6 个格，逐格跳）
4. 主操作：进入
5. 错误行（条件）
6. 脚注：一间房只有两个位置
7. 兜底：码没带过来（一行文字操作，重新打开链接）

**状态**：未登录（先登录/注册，回来仍带房间 ID）/ 待输码 / 码不对 / 限流（每账号每小时 5 次，超了锁 1 小时）/ 码对 → 直接进房（不确认、不等待）/ 满员 / 过期 / 已用 / 我自己已有一间房（给「回我的房间」）

**文案**：`房间 R7K2M9`、`码不对`、`进入`、`一间房只有两个位置`、`码没带过来？重新打开链接`、`这个房间已经满了`、`你已经在另一间房里`、`回我的房间`

## 5. 房间（全产品最复杂的屏）

### B1 `room` 房间

**用途**：两个人说话的唯一点；也是相册与我的的入口。

**结构（正常态，上→下）**
1. **顶部栏**（固定）
   - 左：我的入口（图标按钮）
   - 中：房间名「我们的房间」
   - 右：相册入口（图标按钮）
2. **对方关门条**（条件：对方关着门）
   - 第一行：`对方关着门`
   - 第二行：关门那句（对方写的原话）
   - 第三行：`你的消息会在对方开门时出现`
3. **导出提示行**（条件：对方刚导出，出现一次，不可回复）
4. **消息流**（滚动，占满剩余高度；条目含以下形态，见 5.1）
5. **新消息提示**（条件：上翻历史时收到新消息；底部一个点 + `新消息`，不显条数）
6. **引用态条**（条件：正在引用；输入区上方一整段原文，可展开，带关闭）
7. **AI 问题**（条件：刚开门；一行标「AI」，浮在输入区上方，不挡消息）
8. **门把手**（固定：输入区上沿一条光）
9. **输入区**（固定）：图片入口 / 麦克风 / 输入框（占位「说点什么」，2000 字）/ 发送
10. **卡片输入区**（条件：刚开门，替代第 9 项）：1–2 句、最多 80 字 + `递出去`
11. **半关覆盖层**（条件：把手拉过阈值松手）：整屏变暗 50%，底部一块 `今晚到这儿`（可编辑，不能空）+ `关` / `算了`
12. **关门覆盖层**（条件：门已关）：房间暗，只剩输入框一圈光；显示关门那句；顶部一条细光是把手

**输入区的三种形态**（同一位置切换，不新增区块）
| 形态 | 出现时机 | 内容 |
|---|---|---|
| 普通输入 | 门开着 | 图片 / 输入框 / 麦克风 / 发送 |
| 卡片输入 | 刚开门 | AI 问题 + 1–2 句输入 + `递出去` |
| 关门输入 | 我关着门 | 一行 `说一句，门就开`（不能发普通消息） |

#### B1-a 消息流里必须能画的 9 种条目

| 条目 | 结构 |
|---|---|
| 日期分隔 | 一行居中的日期：`今天` / `昨天` / `10 月 17 日`（跨年带年份） |
| 文字气泡 | 对方左、自己右；气泡内多行文本；气泡下一行是服务端时间 |
| 图片消息 | 一张图 + 下方一行时间（可带地点） |
| 语音消息 | 一个可点的整体：播放标记 + 时长（`0:12`），不需要波形数值 |
| 日期行（28 天到期） | 一行替代原文：`10 月 17 日 · 已收进相册`，可点 |
| 留过的一天 | 一行：`10 月 17 日 · 留过`，可点 |
| 点（没照片的日子） | 月历里用，房间里不出现 |
| 卡片（门） | 一张「纸」：1–2 句，与气泡明显不同；不显示时间 |
| 引用块 | 在气泡内上方：整段原文（可展开），不显示原消息时间；三种内容见下 |

**引用块的三种显示**
- 原文还在：显示整段原文
- 原文已进卡：`10 月 9 日 · 已收进相册`
- 原文已撤回：`原消息已撤回`

**特别记忆折角**：被标过的消息在气泡上带一个折角/标记（弱，不抢戏）。

#### B1-b 状态变体（每个都要一张设计稿）

| # | 变体 | 触发 | 屏上出现 | 屏上不出现 |
|---|---|---|---|---|
| 1 | 正常 | 有消息 | 全部 | — |
| 2 | 空 · 只有我 | 对方没进来 | `不用做什么` + `这儿还只有你` | 输入区以外的一切状态 |
| 3 | 空 · 两人没说话 | 对方已进房 | `不用做什么` | 同上 |
| 4 | 对方关着门 | 对方关门 | 顶部关门条；消息照发，自己消息只有「已发出」 | 对方的新消息 |
